> 寫於 2026-10-16，對應 `ai-bridge` 分支 commit `f9f80e5a`（從 OpenPnP `5bd404cf` 起算共 33 個 commit）。
> 每天的細節在 [worklog/](../worklog/)，最初的計畫在 [AI_BRIDGE_PLAN.md](AI_BRIDGE_PLAN.md)。

## 1. 原則：能用腳本的就用腳本，腳本失敗時才由 AI 接手

- **腳本（程式）負責**：固定的流程，以及有明確判斷標準的事情。例如：讀 QR、找料帶孔、量 Z、底部視覺、放料、比對放置前後的照片、判斷合格與否。這些都不花 token，每次結果都一樣。
- **AI 負責**：
  1. 腳本回報失敗或無法判斷時，看照片、找原因（例如定位孔和背景連在一起、標籤被切到、料帶放反、拿錯料）。
  2. 修改程式或調整參數，並記錄下來。
  3. 抽查：偶爾看幾張照片，確認腳本的判斷還是準的。
- 所以每支腳本都要做到兩件事：**輸出結構化的結果**（狀態、原因、數值），並且**把照片存檔**（`ai-bridge/inspect/`、`scan/`、`captures/`）。這樣 AI 接手時，不用重新移動機器就能查原因。

## 3. 已知問題與發現

| 問題 | 影響 | 目前處理 |
|---|---|---|
| 歸零撞到限位開關時機器會震動，沒有錫膏的零件會跳開（不是每次都會） | 乾放測試時，放好的零件可能移位 | 放好零件後盡量不要重啟或歸零；要重啟就先檢查一次 |
| 真機版 OpenPnP 偶爾關不掉（`quit()` 中途出現例外） | 要強制結束 | stderr 改存到 `log/stderr.log`，下次發生時查原因 |
| 真空感測只讀 MSB（256 階），N045 有零件和沒零件只差 3–4 階 | 量 Z、判斷有沒有吸到零件都不太靈敏 | 暫緩；改成連 LSB 一起讀需要改 Gcode |
| 吸嘴頭都沒有開吸取後的真空檢查 | 吸起來沒有、拋料成功沒有，程式都不知道 | 靠底部視覺和放置後的驗收來補 |
| N045 有偏擺（runout），也沒做吸嘴頭校準 | 零件轉角度時偏移會變 | 底部視覺在最終角度拍照，所以還能修正 |
| 上相機是固定焦距，標籤比板面高，所以會失焦 | QR 還讀得出來 | 不用處理 |
| 上相機的視野在 Y 方向只有 10.6 mm | 標籤要排得夠整齊 | 掃描改拍 5 排，可容許 ±4 mm |
| 很靠近定位孔剪的料帶，孔會跟底板連在一起 | 找不到定位孔 | 已修正（先用 opening 切開） |
| 小零件（0603）的角度量測有幾度雜訊 | 誤判成 `check` | 改成用末端位移判斷，**還沒在真機上驗證** |

## 4. 未來規劃

### 4.1 已經做好、但要再測的

1. **QR 掃描正式寫入**：100 nF 料帶已經轉好，重新試跑一次。確認 3 條都正確、1uF 的第一顆回到 188.46 後，再加上 `apply` 寫入。10 nF 是新增的 feeder，要用 `probe_feeder_z` 量 Z，然後啟用、試吸。
2. **新的角度判斷**（用末端位移）：放下一批零件時確認不會誤判。
3. **前後比對驗收用在其他零件**：R0603、AD608（IC 面積大，變化區域也大），還有零件被撞歪的情況。
4. **`probe_feeder_z` 用在其他料帶**：10 nF、100 nF，以及以後的 R0603。
5. **C0603 視覺設定用在其他電容**：10 nF、100 nF、100 pF、18 nF，用 `test_bottom_vision` 各確認一次。
6. **料帶用完時的行為**：strip feeder 取到最後一顆之後會怎麼樣，要看 OpenPnP 會不會停用 feeder、`place_from_job` 會不會換 feeder。
7. **OpenPnP 關不掉的問題**：下次發生時看 `log/stderr.log`。

### 4.2 改成腳本自動跑（不需要 AI）

目標：一個人放好板子和料帶，執行一個指令就能跑完；只有失敗時才找 AI。

1. **`run_job.py`**：完整流程的腳本。
   - 換新板子時先跑空板拍照（`survey_bare_boards`）。
   - 依零件高度排序，**先放矮的，再放高的**（用零件的 `height`，所以要先補齊高度是 0 的零件）。
   - 放料，再驗收（`inspect_placements`，預設只回傳不合格的照片）。
   - 輸出一份報告：每個 placement 的判定、不合格的照片路徑、被停用的 feeder、用掉的零件數。
2. **`tune_bottom_vision.py`**：把今天手動調門檻的方法寫成腳本。從高到低掃一遍門檻，找出「量到的大小接近 footprint、角度穩定」的範圍，取中間值，有需要時再建立該封裝的視覺設定。結果不確定時（例如找不到可用範圍）才交給 AI。
3. **`scan_feeders.py` 加上量 Z**：新增的 feeder 可以接著自動跑 `probe_feeder_z`、寫入 Z，再試吸一顆，全部通過才啟用。
4. **所有腳本統一的失敗回報格式**：寫到 `ai-bridge/reports/<時間>.json`，內容包括哪一步失敗、錯誤訊息、照片路徑、機器和吸嘴的狀態。AI 接手時從這裡讀。

### 4.4 介面大改

**目標**：介面只留下人一定要看、一定要做決定的東西，其他參數都收進預設收合的「進階」層級。需要時人還是可以展開來調。

**一定要給人看的**

| 項目 | 原因 |
|---|---|
| 選擇或上傳電路板檔案、job | 只有人知道要做哪一片板子 |
| 板子放好之後的預覽照片（含基準點） | 確認板子放對了、方向正確 |
| 料帶和 feeder 的對應表（QR 掃描結果）、缺料、拿錯料、料帶放反 | 這些都要人動手處理 |
| 開始、暫停、停止 | |
| 安全提醒：歸零前確認路徑淨空，零件放好後會不會被震走 | |
| 結果報告：合格、需檢查、缺件的數量，以及**只有不合格的照片** | 人要決定要不要重放 |
| 需要人處理的錯誤：換料、拿走零件、吸嘴上還有零件 | |

**預設收合，人不用看的（進階）**

- 視覺 pipeline、門檻、各封裝的視覺設定
- feeder 座標、Z、rotation in tape、送料間距
- 吸嘴頭、真空門檻、Safe Z、相機校正、Gcode
- 驗收的容許值（0.25 mm）、比對參數

**做法**

- OpenPnP 原本的介面（Swing）全部保留，進階使用者照常可以用。
- 簡化版介面有兩個選擇：
  - **A. 本機網頁**：由 bridge 在 127.0.0.1 提供，畫面的內容直接用 bridge 的 HTTP API 取得。改版快、手機或平板也能看。
  - **B. OpenPnP 裡新增一個「簡易」分頁**（Swing）。
  - 我建議 **A**：bridge 已經有所有需要的 API，網頁版本比 Swing 好改。
- 全景圖也一起整合進去（之前延後的項目）。

### 4.5 其他待辦

- 料帶反向的支援：從料帶尾端開始取，取到標籤前就停（目前會要求轉 180°）。
- 真空感測改成連 LSB 一起讀（要改 Gcode，風險較高，先備份）。
- pin 1 極性自動判斷（IC、二極體、電解電容）。
- 角度量測做更細的擬合（目前 BodyLocator 以 0.5° 為一階）。
- 補齊零件高度：除了 C0603-1uF，其他 C0603、R0603 的高度都是 0。
- R0603 的底部視覺（現在用的是預設門檻 240，很可能也找不到零件）。
- 如果之後要用 0805，要另外建封裝和視覺設定。
- 部分 AD608 feeder 之前被 job processor 自動停用，要記得重新啟用。
- 回饋給 upstream 前，整理 Java 程式碼，確認符合 OpenPnP 的格式和貢獻規範。
